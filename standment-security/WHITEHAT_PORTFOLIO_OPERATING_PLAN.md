# Standment Security — White-Hat Portfolio Operating Plan

Status: **P0 / continuous R&D**

## Purpose

Use THE WORLD's `elite_whitehat` researcher to continuously turn adversarial thinking into defensible, customer-inspectable Standment security portfolio assets.

The white-hat cell is not measured by the number of vulnerabilities it names. It is measured by the number of security claims that become **reproducible evidence, remediation, retest and customer value**.

## Shared intent

The operating intent inherited from THE COVENANT and the Supreme Research Freedom Doctrine is:

`QUESTION -> HYPOTHESIS -> SAFE EXPERIMENT -> EVIDENCE -> FALSIFICATION -> REMEDIATION -> RETEST -> PORTFOLIO -> REAL_WORLD_VALUE`

The research mind is intentionally broad. Execution remains inside owned or explicitly authorized scope.

## Collaboration model

### Elite White-Hat

- challenge the selected security boundary
- define a falsifiable attack/control-failure hypothesis
- identify authorization basis and safe reproduction conditions
- preserve counterevidence
- propose the smallest defensive remediation
- define independent retest and residual-risk criteria

### White-Hat Lab Evidence Layer

- convert the elite white-hat output into a structured defensive finding set
- create a **plan-only falsification map with zero network requests**
- prove active validation remains hard-limited to loopback/private/link-local targets
- cap active lab validation to a maximum of 12 requests using bounded methods
- forbid credential guessing, authentication bypass, exploit execution, destructive mutation, path fuzzing and phishing delivery
- preserve the falsification plan and local-lab receipts as evidence inputs
- never treat the generic local harness as proof that a candidate vulnerability exists
- use the real next step to map the highest-impact hypothesis to owned source/config or an authorized local fixture, then produce same-condition Before/After proof

### Senju

- challenge research quality, reproducibility and learning efficiency
- compare competing hypotheses and evidence paths
- help avoid repeating stale research approaches
- never receives credentials, third-party target selection or authorization expansion

### R&D / Agent Factory

- provide competing researchers and independent evidence scoring
- preserve rejected hypotheses and negative evidence
- route one bounded implementation through tests and policy gates

### Portfolio Auto-Builder / FORGE

- translate verified engineering evidence into case studies, evidence packs, scorecards and buyer-readable artifacts
- never turn an internal score or untested claim into `VERIFIED`

### SKEPTIC / Reviewer

- reject unsupported completion claims
- check whether the claimed customer value actually follows from the evidence

## Daily minimum output

Every daily white-hat portfolio cycle must produce at least one of the following, or explicitly report why it could not:

1. a new `WHITEHAT_CANDIDATE`
2. a stronger reproduction/retest criterion for an existing candidate
3. new counterevidence that invalidates or narrows a candidate
4. a verified before/after defensive delta ready for portfolio promotion
5. a documented blocker with an exact next experiment

The cycle should also preserve a falsification plan. When active validation is relevant, a local/owned lab receipt should be attached before any stronger claim is considered.

Activity without one of these outputs does not count as portfolio progress.

## Candidate contract

Every candidate must show:

- purpose
- research question
- owned/authorized scope basis
- trust boundary
- safe experiment
- evidence references
- counterevidence / dissent
- proposed defensive change
- independent retest criteria
- rollback/recovery
- limitations
- expected customer / real-world value

## Promotion contract

`WHITEHAT_CANDIDATE -> BUILDING -> VERIFIED`

Promotion to `VERIFIED` requires human-inspectable evidence for:

- authorization/scope
- before-state
- safe reproduction
- remediation
- after-state
- independent retest
- counterevidence
- residual risk / limitations
- rollback or recovery behavior

Internal tournament scores, code existence, agent confidence, plan-only hypotheses, generic local-lab harness results and prose alone do not satisfy the promotion gate.

## Reporting to CEO / Slack

Reports must answer, in this order:

1. **WHAT CHANGED** — what artifact, control, test or evidence changed
2. **WHY IT MATTERS** — what risk or uncertainty was reduced
3. **PORTFOLIO DELTA** — what became more customer-inspectable
4. **WHITE-HAT FINDING** — what boundary/hypothesis was challenged
5. **FALSIFICATION PLAN** — how the claim can be disproven and whether the plan used zero network requests
6. **RETEST STATUS** — passed / failed / not-run, with evidence
7. **REAL-WORLD VALUE** — what buyer/operator can now understand or trust better
8. **TRUTH / LIMITATION** — what is still unverified
9. **NEXT MOVE** — the next bounded experiment or portfolio promotion step

Do not report raw activity volume as progress.
